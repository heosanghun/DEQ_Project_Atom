# ESC-0005 — GPU 1 이상과 P5(held-out 520 확증) 재개 장치 (Principal 결정)

상황: 서버가 10/5 04:50에 재부팅됐다. 그 뒤 GPU 1은 `GPU requires reset` 상태로 쓸 수 없다. 재부팅 전에도 GPU 1은 GPU 2보다 약 3배 느렸다. P5는 520문항 중 150문항이 저장된 채 멈췄고(GPU 1에서 계산), P5b(시드 2031)는 390문항이 저장된 채 멈췄다(GPU 2). P4' 디코더 학습은 GPU 0에서 재개됐다(D·E까지 끝나는 시점은 10/6 새벽 4시경).

질문 1: GPU 1 재설정이나 점검을 서버 관리자(이정제님)에게 요청할까요? 재부팅 원인이 GPU 1일 가능성이 있습니다.
질문 2: P5의 남은 370문항을 어디서 계산할까요?
- [A] GPU 2에서 이어 계산(권고, 가장 빠름): P5b의 남은 130문항(약 45분)을 먼저 끝내고, 이어서 P5 370문항(약 2~3시간)을 계산한다. GPU 2는 장치 동등성을 bitwise로 충족했다(GPU 1과 20/20 동일). 사전등록 v1.3 §10(f)에는 ⑦을 GPU 1에서 돌린다고만 적혀 있으므로, 결과를 열기 전에 "⑦의 장치를 동등성 충족 GPU(GPU 2)로 바꿀 수 있다"는 v1.4 개정(복사+diff, B 감사)을 거친다. 한 실행 안에서 앞 150문항은 GPU 1, 나머지는 GPU 2가 된다는 점도 기록한다.
- [B] 사전등록 문언대로: GPU 1 미달 시 규칙대로 P4' 종료 뒤 GPU 0에서 이어 계산한다. 개정이 필요 없지만 약 15시간 늦어진다(10/6 오후).
- [C] 관리자가 GPU 1을 고친 뒤 GPU 1에서 이어 계산한다(언제 될지 모름).
영향: [A]·[B] 모두 되돌릴 수 있다. P5b의 남은 130문항은 GPU 2에서 이어 계산한다(이미 승인된 장치·작업, 이 ESC와 무관).
갱신(CC, 10/5 23:2x, AUDIT-0036): 16:33 재부팅 뒤 GPU 1의 'requires reset' 상태는 사라졌다(REPORT-0034·0036, 유휴 0%, 13 MiB). 관리자 재설정 요청은 더 이상 필요 없다. P5는 기본 경로(v1.3 §10(f), GPU 0 직렬, E 종료 뒤 약 10/6 05:50~)로 진행한다. 서버가 불안정하므로 CC는 [B](GPU 0 유지)를 권고한다.
