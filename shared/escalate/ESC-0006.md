# ESC-0006 — 서버 하루 2회 불시 재부팅 (Principal·관리자 조치 필요)

상황: Quadro-Ampere-05가 10/5 04:50과 16:30경, 두 번 예기치 않게 재부팅됐다. 첫 재부팅 뒤 GPU 1은 `GPU requires reset` 상태로 남아 있다(ESC-0005). 두 번째 재부팅 직전(16:29:41)에는 GPU 0 사용 메모리가 16.7 GB에서 42.9 GB로 갑자기 늘었다. 우리 디코더 D 학습만으로는 약 17 GB이므로, 우리 것이 아닌 프로세스가 GPU 0을 썼을 가능성이 있다. 첫 재부팅의 저널에는 Xid·OOM·패닉 기록이 없었다. 재부팅 때마다 마지막 체크포인트 이후 작업(최대 500 step, 약 1시간)과 대기 장치가 사라진다.

질문 1: 서버 관리자(이정제님)에게 다음을 요청할까요? 재부팅 원인 점검(BMC/IPMI 이벤트 로그, 전원·온도), GPU 1 재설정 또는 점검, 같은 시각 GPU 0을 쓴 다른 사용자 작업이 있었는지 확인.
질문 2: 점검 결과가 나오기 전에도 우리 작업을 재개할까요?
- [A] 재개(권고): GPU 0 한 장만 쓴다(부하 최소). 디코더 D를 step 1500 체크포인트에서 이어 학습 → E → P5(GPU 0) 순서로 진행한다. 재부팅이 한 번 더 나면 모든 작업을 멈추고 관리자 점검을 기다린다.
- [B] 보류: 관리자 점검이 끝날 때까지 서버 작업을 하지 않는다.
기본값(답이 없을 때): [A]. 이미 승인된 장치(GPU 0)에서 사전등록 순서대로 하는 작업이고, GRAPH N0(서버 복구 → 증분 재개)에 해당하기 때문이다. 단, 진단에서 하드웨어 오류(Xid·전원·열)가 보이면 [B]로 바꾼다.
영향: 되돌릴 수 있음. 서버 물리 조치는 관리자 권한이다.
정정(CC, 10/5 23:2x, AUDIT-0036): 위 '우리 것이 아닌 프로세스' 추정은 철회한다. 디코더 D 로그의 peak_mem이 39.6 GiB이므로, 16:29의 42.9 GB는 우리 학습의 최고 사용량과 맞는다. 재부팅 원인은 여전히 불명(소프트웨어 기록 0, 정상 종료 기록 없음)이며 질문 1의 점검 요청 권고는 유지한다.
