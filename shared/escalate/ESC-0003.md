# ESC-0003 — SSH_LOCK 해제와 잠금 규칙 보정 (Principal 결정 필요)

상황: 2026-10-04 20:49 shared/SSH_LOCK이 생성되었다. 원인은 접속 장애가 아니다. 서버에서 돌린 시험 스크립트가 두 번 연속 오류(rc 1)로 끝났고, cts_ssh.py가 이를 "접속 실패 2회"로 세었다. 서버 쪽 P4' 학습과 P5 자동 대기 장치는 서버 안에서 계속 돌므로 영향이 없다. 막힌 것은 회사 PC → 서버 새 접속뿐이다. 다음에 서버가 필요한 작업은 P6 실행기 수정 반영이다(급하지 않음, P5는 10/6 02시경 자동 시작).

질문 1: SSH_LOCK을 해제해도 될까요? (규칙상 Principal만 해제할 수 있습니다.)
질문 2: cts_ssh.py의 잠금 규칙을 바꿔도 될까요? ssh 자체의 접속 오류(종료코드 255)만 "접속 실패"로 세고, 원격 명령의 오류(그 밖의 0이 아닌 값)는 기록만 하고 잠그지 않게 하는 안입니다. 지금 규칙은 직전 2행이 0이 아니면 다시 잠그므로, 잠금 파일만 지워서는 다음 접속에서 또 잠깁니다.

선택지:
- [A] 둘 다 승인 (권고): CC가 cts_ssh.py를 새 파일로 고쳐 바꾸고(원본은 .bak 보존, 로컬 모의 시험 후 교체) SSH_LOCK을 지운다. 60초 간격·시간당 20회·로그 의무는 그대로다.
- [B] 해제만 승인: CC가 ssh_log.csv에 "Principal 해제" 행(exit 0)을 추가하고 SSH_LOCK을 지운다. 규칙은 그대로 두며, 같은 일이 다시 생길 수 있다.
- [C] 보류: 서버 작업 없이 로컬 작업만 한다. P5는 서버에서 예정대로 자동 시작한다. 그 뒤 z_src 600·P6 시작은 접속이 풀려야 할 수 있다.
영향: 되돌릴 수 있음. 서버 접속 빈도 상한은 바뀌지 않음.
