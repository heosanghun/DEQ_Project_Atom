## 1. `scripts/p5_prep_inputs_v3.py` (새 파일) — 서버에서 실행
- 로그 파싱 검사:
  - 로그 파일별 SHA를 머리말에 넣는다. 문항 키는 (로그 파일, Q#)로 둔다. 400/680 실행 출처를 기록한다.
  - 문항당 정확히 1블록(100점)이어야 하고, 아니면 종료한다. 같은 Q#가 여러 로그에 있으면 종료하고 보고한다.
  - 로그의 라벨 1000 값과 pt `rho_1000`이 상대 1e-7 이내로 같은지 대조하고, 다르면 종료한다.
  - 걸음 표기는 로그 "Step L" = α·r_{L−1}이므로 **k = L − 1**로 적는다.
- **k* 판정 규칙(보강)**: 4·min ρ < r_1000인 문항마다 로그 최솟값 ρ_log_min과 pt `min_rho`를 비교한다(로그 출력 `%.8e` 기준 상대 1e-7).
  - 같으면 k* = (해당 L) − 1로 확정한다. `k_star_src: "log_10step_exact"`.
  - 로그 최솟값이 더 크면 `k_star: null`, `k_star_src: "undetermined"`로 둔다(실제 최소가 기록되지 않은 걸음에 있음).
  - 로그 최솟값이 더 작으면 대응 오류이므로 종료한다.
- 출력은 새 파일 `results_s7/p5_inputs_train1000_v3.json`이다. 분류별 개수(exact, undetermined, final)와 exact 중 k* < 50의 수를 보고한다.
