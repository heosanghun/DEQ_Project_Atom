## 1. 새 파일 `scripts/s7_eval_gate_p6_v36.py` — 생성기 (사양)

- 디코더 체크포인트를 적재하기 직전에 `scripts/check_p6_decoder_version.sh <경로>`를 호출한다. 반환코드가 0이 아니면 종료한다.
- **프롬프트**: A·B·D·E·F는 §3(a)(`"1"*64 + "\n\n" + problem`, apply_chat_template, add_generation_prompt=True), C는 §3(c)(problem만, 슬롯 0). 각 조건의 첫 문항에 대해 앞 80개 토큰 ID를 로그에 남기고, §3(b) 정본 배열(슬롯 [4,67], 68번 = 108)과 대조한다.
- **조건과 z 공급원**:
  - A = 디코더 A + 자기 z*
  - B = 디코더 A + z*_{(i+s)%N}
  - C = 순정 Gemma, 글만
  - D1·D2 = 디코더 D + 자기 z* / shift
  - E1·E2 = 디코더 E + 자기 z_src / shift
  - F = 디코더 A + S_train 1,000 z_star 평균(held-out 80 제외)
  - B와 D2의 shift: 주 게이트용은 s=1, 보조용은 s=2·3을 `--shift` 인자로 받는다.
- **문항 순서 고정(N=600의 shift 기준)**: held-out 600 문항 ID 오름차순. 이 순서를 `results_s7/p6_item_order.json`(ID 목록과 SHA)으로 먼저 저장하고, 모든 조건이 이 파일을 읽는다. 시험 모드에서는 train 문항으로 같은 방식을 쓴다.
- **z* 공급(held-out)**: 520은 P5 출력 `results_s7/zstar_s7_a0.25_heldout520_lowest.pt`의 `z_star`(최종점, v1.2 §10(c) "변별·디코더 입력은 최종점")를 쓴다. 80은 기존 S7 z* 파일에서 가져온다(정확한 파일·키 형식·SHA를 찾아 적는다). z_src(600)는 `results_s7/zsrc_heldout600.pt`(아래 3번)를 쓴다.
- **디코딩**: greedy, `do_sample=False`, `max_new_tokens=512`(§7). 출력은 조건별 jsonl(`results_s7/p6_gen_{조건}{shift}.jsonl`: id, prompt_sha, 생성문, 토큰 수, 시간)로 남기고, 증분 저장과 재개(이미 있는 id는 건너뜀)를 지원한다.
- **보조 NLL**: `--nll` 모드에서 정답 해설 토큰의 float32 청크 NLL을 문항별로 저장한다(A·B·C·E1). 학습 스크립트의 NLL 함수를 재사용한다.
- 인자: `--cond {A,B,C,D1,D2,E1,E2,F} --shift N --items <config> --out <jsonl> --device --smoke`. `--smoke`가 없을 때 items가 held-out이면, `raw_s7/P5_DONE.flag`와 `results_s7/zsrc_heldout600.pt`가 없는 경우 종료한다.
