## F1. 형식 통제 재평가 (원인 후보 ① 확인)

**질문**: P6 게이트 3의 작은 우위(A−C +1.17 %p)와 바닥 정답률은 답 표기·길이 형식 때문인가? 형식을 통제해도 E1 > A인가?

- 문항: P6과 같은 held-out 600(`results_s7/p6_item_order.json` 순서).
- 조건: C(글만), A(자기 z*, 디코더 A `results_s7/decoder_A_v36.pt` SHA `2953ff07…`), E1(자기 z_src, 디코더 E `results_s7/decoder_E_v36.pt` SHA `f8115ac3…`). 입력 텐서는 P6과 같은 파일(z*: P5 출력과 기존 80, z_src: `results_s7/zsrc_heldout600.pt` SHA `0da3748a…`).
- P6 대비 바꾸는 것 두 가지만:
  1. `max_new_tokens` 512 → **1024**
  2. 문제 글 끝에 같은 안내 문장을 붙인다: `\n\nPlease reason step by step, and put your final answer within \boxed{}.` (세 조건 모두 같게. 슬롯·프롬프트 양식은 P6과 같음)
- 그대로: 탐욕 생성, 정지 토큰 {1, 106, 107}, KV 캐시 생성 함수, 순정 Gemma-4-e4b(`58c4d7b5…`), 채점기 `scripts/s5_eval_grader_v2.py`(SHA `90cc93e4…`).
- 생성 실행기: P6 실행기 `scripts/s7_eval_gate_p6_v36b.py`를 복사한 새 파일 `scripts/s7_eval_followup_f1.py`(`--instruction`·`--max_new_tokens` 외 변경 0, CC가 diff로 확인).
- 지표(보고):
  - 조건별 strict·lenient 정답률, `\boxed{}` 포함 비율, 1024 토큰 도달 비율
  - A−C, A−E1, E1−C의 strict 차이: 대응 부트스트랩 10,000회(시드 2026) 95 % CI, 정확 McNemar 단측 p, 불일치 b/c
- 미리 정한 읽기 규칙(설명용):
  - **R1-a** F1의 C strict가 P6보다 5 %p 이상 오르면 "P6 바닥은 형식이 지배" 지지.
  - **R1-b** F1의 A−C strict CI가 0을 포함하거나 음수면 "P6 게이트 3 우위는 형식 효과" 지지. CI 하한 > 0 ∧ p < 0.025면 "형식 통제 뒤에도 z* 기여 신호" (G2 재판정 아님).
  - **R1-c** F1의 E1−A strict가 CI 하한 > 0 ∧ p < 0.025면 "형식 통제 뒤에도 z_src > z*" 지지(원인 후보 ② 현상 유지). 그렇지 않으면 "E1 > A는 형식 차이로 설명 가능".
- 장치: GPU 0(P6 체인 종료 뒤). GPU 1이 F3 뒤 비어 있으면 조건 단위로 나눠 돌려도 된다. 조건 하나는 한 GPU에서 끝까지 돈다.

## F2. 잠재 상태의 문제 정보량 탐침 (원인 후보 ② 확인)

**질문**: z*는 z_src보다 문제에 대한 정보를 덜 담는가?

- 데이터
  - 학습(탐침 적합): train 1,000 — z*: `results_s7/zstar_train1000_P4.pt`(SHA `37ea6807…`, 필드 `z_star`), z_src: `results_s7/zsrc_train1000_P4.pt`(실행 전 SHA 기록)
  - 평가: held-out 600 — z*: P6 조건 A가 쓴 텐서와 같은 것, z_src: `results_s7/zsrc_heldout600.pt`
- 표현: 64개 슬롯 평균(2,560차원), 학습 집합 평균·표준편차로 표준화. 보조로 펼친 163,840차원에 학습 집합 PCA 256차원.
- 목표 1(주): **문제 글 임베딩 복원**. 문제 글을 순정 Gemma-4-e4b(같은 스냅샷)에 넣어 마지막 은닉층을 토큰 평균한 2,560차원 벡터 e(문제 글만, 채팅 양식, 생성 없음). 잠재 상태 → e를 릿지 회귀로 예측(α는 학습 집합 5겹 교차검증, 격자 {1e-2, 1e-1, 1, 10, 1e2, 1e3, 1e4}). 평가: held-out 600에서 예측 ê의 코사인 최근접이 자기 e인 비율(**top-1 검색률**), top-5 검색률, 평균 cos(ê, e).
- 목표 2(보조): 데이터셋 레코드에 과목(`type` 또는 같은 뜻의 필드)과 난이도(`level`) 필드가 있으면 다항 로지스틱 회귀(L2, C는 5겹 교차검증, 격자 {1e-3, …, 1e2})로 정확도. 필드 이름은 실행 전에 확인해 보고서에 적는다. 없으면 목표 2는 "필드 없음"으로 적고 하지 않는다.
- 비교: z_src 대 z*의 top-1 검색 정답 여부를 문항별로 대응시켜 부트스트랩 10,000회 95 % CI와 정확 McNemar 단측 p. 다수 클래스·무작위 기준선(1/600)도 적는다.
- 미리 정한 읽기 규칙(설명용):
  - **R2-a** z_src − z* top-1 검색률 차이의 CI 하한 > 0 ∧ p < 0.025 → "z*는 z_src보다 문제 글 정보를 덜 담는다" 지지.
  - **R2-b** 차이의 CI가 0을 포함 → "정보량 차이로 G2 게이트 4를 설명할 근거 없음".
  - **R2-c** z*가 더 높으면 → 원인 후보 ② 반대 근거로 적는다.
- 장치: 임베딩 계산만 GPU 1(문제 1,600개, 생성 없음). 탐침 적합·평가는 CPU.

## F3. 반복 횟수별 정보량 곡선 (원인 후보 ② 위치)

**질문**: 문제 정보가 반복 몇 번째에서 줄어드는가?

- 문항: train 1,000에서 300개, held-out 520에서 200개. 선택은 `numpy.random.default_rng(20261007)`로 각 목록(정렬한 q_idx)에서 비복원 추출하고, 결과 목록을 `configs/followup_f3_train300.json`·`configs/followup_f3_heldout200.json`에 저장해 SHA를 실행 전에 적는다.
- 계산: 정본 실행기와 같은 인자(α 0.25, g₀ 0.25, seed 2030, σ 0.020, max_nfe 1000, tol 0, `configs/zstar_canonical.yaml`)로 궤적을 다시 돌리며 **k ∈ {0, 10, 30, 100, 300, 1000}**의 z_k를 저장한다(k=0은 잡음을 더한 초기값 z_0). 실행기는 `cts/deq/zstar_canonical_lowest.py`를 새 파일로 복사해 저장 지점만 더한다(전이·잔차·최저점 코드 변경 0).
- 계기 점검(착수 전): 앵커 Q#20·24·32를 새 실행기로 GPU 1에서 돌려 z_1000이 `results_s7/anchor_ref_gpu1_check.pt`(SHA `5103642d…`)의 z_star와 max|Δ|=0인지 확인. 아니면 멈춘다.
- 본 계산 중 점검(보고): 각 문항의 z_1000과 기존 z_star(train: P4 파일, held-out: P5 출력)의 cos. P5의 151~520번은 GPU 0에서 계산됐으므로 장치 차이를 함께 적는다.
- 분석: F2와 같은 탐침(목표 1: top-1 검색률, 평균 cos; 목표 2는 필드가 있을 때)을 k마다 train 300으로 적합하고 held-out 200(검색 후보 200개)에서 평가한다. z_src(반복 없음, 잡음 없음)도 같은 방식으로 한 점 더 찍는다. 보조로 k마다 잔차 r_k와 ‖z_k − z_0‖/‖z_0‖.
- 미리 정한 읽기 규칙(설명용):
  - **R3-a** "감소 지점" = top-1 검색률이 k=0 대비 처음으로 대응 부트스트랩 95 % CI 상한 < 0이 되는 가장 작은 k. 없으면 "감소 지점 없음".
  - **R3-b** k=1000 값이 k=0보다 낮고(CI 상한 < 0) 그 사이 값이 대체로 단조로 줄면 "반복이 문제 정보를 점차 줄인다" 지지.
- 장치: GPU 1. 예상 500문항 × 약 64 s ≈ 9시간.
