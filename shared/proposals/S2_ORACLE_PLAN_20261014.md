## 1. 가르려는 질문

지금까지 "잠재가 디코더에 읽히지 않는다"는 것은 확인됐지만, 그 원인이 **(가) 연결부(투영기 + 64칸 prefix → 고정 LM)가 내용을 전달하지 못해서**인지 **(나) DEQ 잠재에 읽을 만한 내용이 없어서**인지는 가르지 못했다(양성 대조는 NLL z 2.7의 약한 신호뿐). S2는 **정답 정보를 확실히 담은 "오라클 잠재"**를 같은 연결부로 넣어 이 둘을 가른다.

- 오라클 잠재로도 정확도가 오르지 않으면 → (가). 연결부를 바꿔야 한다(10/17~ 새 연결부 시제품).
- 오라클 잠재로는 뚜렷이 오르면 → (나). 연결부는 쓸 수 있고, DEQ가 읽을 만한 내용을 만들도록 목표를 바꿔야 한다(10/23~ DEQ 목표 시제품).
- 덤으로 "이 연결부의 상한(오라클 정확도)"을 얻는다.

## 2. 오라클 잠재의 정의

- **ORC**: 순정 Gemma-4-e4b(58c4d7b5)에 **정답 해설(gold solution) 글**을 통과시켜 얻은 마지막 층 은닉 상태의 **마지막 64토큰**(64 × 2560). 해설이 64토큰보다 짧으면 첫 상태를 반복해 앞을 채운다. (`g2v4_posctl_latents.py`와 같은 방식, 입력만 문제 글 → 해설 글.)
- 이 잠재는 의도적으로 정답을 "누설"한다. S2의 목적은 성능 주장이 아니라 **연결부가 내용을 통과시킬 수 있는지**를 보는 것이다. 결과는 어떤 G2 주장에도 쓰지 않는다.
- 저장 형식: 키 `q{idx:04d}_a0.25`·`q{idx:04d}`, 필드 `z_star`·`z_src`(같은 텐서) — 기존 생성기(v36g)·진단기가 그대로 읽는다.

## 3. 조건

| 조건 | 학습 | 평가 입력 | 뜻 |
|---|---|---|---|
| ORC-m | 오라클 잠재 + V2 투영기, **DEQ 한 걸음 없이**(`--no_step`: 잠재를 그대로 투영기에) | 자기 문항의 오라클 잠재 | 연결부가 내용을 전달하면 높아야 함 |
| ORC-s | 같은 디코더 | 다른 문항(한 칸 민)의 오라클 잠재 | 문항 내용 효과의 대조 |
| C-fmt | 없음 | 잠재 없음, 형식 지시만 | 이미 있음(S1): lenient 15.67 %, strict 12.83 % |

- 레시피는 S1과 같다: 형식 지시 고정(`Put your final answer within \boxed{}.`), 3,000단계, 배치 4, lr 1e-4/3e-4, 글 가리기 0.5, λ_ift 0. DEQ 사상은 학습하지 않는다(no_step이므로 LoRA·routing·γ 기울기 없음).
- 시드 3(2047·2049·2050). GPU 5·6·7 병렬.

## 4. 지표 (CTO 지침 CTS-434 그대로)

- 주 지표 **lenient** 정확도, 보조 strict·`\boxed` 비율. 먼저 조건별 `\boxed` 비율을 확인한다.
- 검정: 문항 단위 cluster bootstrap 10,000회(600문항 복원 추출, 같은 문항 집합에서 3시드 차이의 평균). 시드 2026.
- NLL 입력 교체(matched·shuffled·평균·zero·no-injection)도 보고.

## 5. 판단 규칙 (미리 정함)

| 결과 | 판단 | 다음 |
|---|---|---|
| ORC-m − ORC-s(lenient) CI 하한 > 0 **그리고** ORC-m − C-fmt ≥ +5 %p | 연결부는 내용을 전달한다 → 병목은 DEQ 잠재의 내용 | DEQ 목표 변경 시제품(10/23~) |
| ORC-m − ORC-s CI 하한 ≤ 0 **또는** ORC-m − C-fmt < +5 %p | 오라클로도 못 읽는다 → 병목은 연결부 | 새 연결부 시제품(10/17~) |
