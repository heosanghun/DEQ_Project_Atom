## 필요한 수정
- **FIX-1 (217행, 11행) 판정 r의 출처를 하나로.** 1,000문항 모두 r은 v1.3 §10(c) 175행 정의의 기존 r_min을 쓴다. 재계산은 325개의 k*만 정한다. 재계산 r_lowest와의 차이는 보고만 한다. (대안: 재계산 r를 쓰려면 FIX-2 재현 통과 문항에 한정하고 그 사실을 적는다.)
- **FIX-2 (217~218행) 문항별 재현 확인과 불일치 처리.** 각 문항에서 재계산 `min(rho_traj)`와 P4 `min_rho`의 상대차 ≤1e-7(prep v3와 같은 기준)이면 "재현"으로 본다. `z_star` 대 P4 `z_star`의 max|Δ|·cos도 적는다. 재현이 안 된 문항의 처리를 미리 정한다. 권고: 1차 집계에서 미도달로 세고, 재계산 k*를 그대로 쓴 값은 민감도로만 보고한다.
- **FIX-3 (216행) 장치 사전 점검과 대체 순서.** 점검 대상을 P4 원 실행과의 동등성으로 바꾼다. 권고: 판별된 49개(`log_10step_exact`) 중 q_idx가 가장 작은 5개를 그 GPU에서 다시 계산해, `min_rho` 상대차 ≤1e-7과 k* 일치를 모두 요구한다. 앵커를 쓰려면 v1.3 §10(f)처럼 20개 전수로 한다. 순서: 먼저 끝난 GPU에서 점검 → 미달이면 다른 GPU가 끝난 뒤 그 GPU에서 점검 → 둘 다 미달이면 재계산하지 않고 ①-a를 "판정 불가(보수 675/1000, 낙관 991/1000)"로 보고한다. 본 실행이 시작되면 장치를 바꾸지 않는다.
- **FIX-4 (215행) 1회 실행 통제와 실행 명령.** 실행 명령 전체(`--items`, `--out`, `--device`, 모든 인자, GPU UUID 고정), config 절대경로와 SHA, `cts/deq/zstar_canonical_lowest.py`·`harness_A_v1` SHA를 적는다. 시작 flag(예: `raw_s7/KSTAR_REPLAY_STARTED.flag`)를 두고 재실행을 금지한다. 중단 시에는 같은 GPU·같은 출력 파일로만 이어 돌린다. 출력 파일 삭제·덮어쓰기 금지. 끝내 빠진 문항·NaN·inf는 미도달로 세고 따로 적는다. 로그 원문과 출력 SHA를 보고한다.
- **FIX-5 (219행) 분석기 고정 시점.** 분석기는 합성 입력 시험과 감사를 마치고 SHA를 **재계산 착수 전**에 고정한다. 분석기는 325 목록 SHA, 출력 키 325개, P4 대조(FIX-2)를 단언하고, 하나라도 어긋나면 멈춘다.
- **FIX-6 (11행, 212행, 218행) 공개와 보고 보강.** 다음을 본문에 적는다. (가) v1.3만으로는 ①-a가 보수 675/1000·낙관 991/1000으로 판정 불가다. (나) 기존 r_min≥1e-2인 9개는 모두 325 안에 있다. (다) 판별된 675개의 k*<50은 0, 최솟값 369다. (라) 재계산 결과는 아직 아무도 보지 않았다. 보고에는 보수·낙관·v1.4 값을 나란히 적고, ①-a를 "비확증 보조, 사후 절차(v1.4)"로 표시한다. 218행 "장치 차이만 남는다"를 "장치와 노름 정밀도(float32/float64) 차이가 남는다"로 고친다.
- **FIX-7 (7행, 213행) 문서 위생.** 7행 잠금 상태를 v1.4 초안 상태로 고치고 선행 잠금본을 v1.3 SHA로 적는다. 213행 `p5_promote_v6.json`에 SHA-256 전체 값(`e929f890ee9323709e4c21a7af3099c2ce0c17423d2bb53c001db7ad4125aef4`, REPORT-0046:187)을 적는다. 216행 CTS-428의 해당 문언 위치를 적는다.

### 질문 1: 상대차 허용치 $10^{-2}$는 적절한가
