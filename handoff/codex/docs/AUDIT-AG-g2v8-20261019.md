## 0. 먼저 읽는 요약

AG 파이프라인의 생성 경로를 코드로 따라가면 **조건 A의 출력 = "순정 C-fmt 생성(캐시)" + 끝부분에 강제로 붙이는 결론 신호("\n\nTherefore, the final answer is $\boxed{") + 순정 LM이 34토큰 안에 마무리**다. DEQ 잠재 z\*의 문항별 내용은 (1) "주입을 켤지 말지" 게이트와 (2) 사실상 문항 불변으로 학습된 슬롯 읽기(`w_tok`)를 통해서만 들어간다. E(K=0)는 게이트 `g_eq`가 닫혀 C-fmt와 비트 동일하게 **설계되어** 있고, A−E = A−C = "주입 켬/끔"이다. A−B1(lenient +1.3~1.7 %p)은 "매처 게이트가 자기 z\*에서 더 자주 열린다"는 뜻이지 z\* 내용이 정답을 바꿨다는 뜻이 아니다. 또한 `--eval_n_dev 60`으로 **dev 앞 60문항의 해설 NLL로 best 체크포인트를 고르므로** dev 600 평가는 오염되어 있다(시드 2050은 이 선택으로 실제 다른 체크포인트가 선택됨).

## 2. 유지 가능한 해석 / 폐기·재해석

### 유지 가능
1. **공학적 사실**: zero-init 게이트 C(α=0 또는 z=center에서 C-fmt와 비트 동일)는 self-test와 Gate C 감사로 확인됨(log:10,16). 비침습 구조 자체는 건전.
2. **E ≡ C-fmt(비트 동일)** — 단 "K=0 잠재가 효과 없다"가 아니라 "게이트가 K=0을 설계상 차단한다"는 사실로만.
3. 고정 채점기(90cc93e4) 경로로 채점했고 dev 600·train 993 범위 안에서 실행됨(새 test 0).
4. Stage 1 ORC 76 %는 "w_tok이 해설 은닉상태에서 토큰을 선형 복원한다"는 사실의 확인으로만 유지(연결부 용량 증거 아님).

### 폐기·재해석
1. **"DEQ z\*가 문항별 기여를 한다"(A−B1 CI 하한 > 0)** → 폐기. A−B1은 매처 게이트의 개폐 차이 × 결론 강제 수율. 읽히는 슬롯 내용은 문항 불변으로 학습됨(2-c).
2. **"DEQ 반복의 효과"(A−E)** → 폐기. A−E ≡ A−C, "주입 켬/끔". E는 구조적으로 C.
3. **"3시드 재현"** → 재해석. 기구가 결정적이라 시드가 거의 작용하지 않음(3).
4. **"zero Dev access"** → 거짓. dev-60 해설 NLL로 best 선택(1-b), 시드 2050은 선택 결과가 달라짐.
5. **"Contractive DEQ = CTS DEQ"** → 폐기. 새 소형 회귀 모듈이며 고정점은 자명(7).
6. **A−C lenient +1.5 %p** → 형식 효과(결론 강제로 미완 CoT를 마무리)로 재해석. CTO 선확인 조건(boxed 비율 유사) 불충족이라 lenient 주 지표로도 내용 효과로 못 읽음(4).
7. Stage 1 "오라클 76 %" → 정답 토큰 복사. X3 판단 규칙의 "통로 열림(matched−C ≥ +5 %p)"을 이 결과로 충족했다고 보면 안 됨.

## 4. 결론 한 줄

**AG 결과를 그대로 쓸 수 없음** — E≡C가 구조적이고(A−E는 주입 유무), 읽히는 슬롯 내용은 문항 불변 결론 신호이며(A−B1은 게이트 개폐 차이), dev-60 해설 NLL로 체크포인트를 골라 dev 평가가 오염됐고, "DEQ"는 정본 CTS DEQ와 별개의 새 모듈이다. 브리지 공학(zero-init 보존, 채점기 경로)만 유지 가능하며, R1~R4 재분석 후 "형식 효과"로 재해석해 기록할 것을 권고한다.
