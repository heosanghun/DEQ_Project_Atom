# RULES.md — CTS 자율 루프 하네스 v1.0 (변경은 복사+diff, B 승인 후)

## 0. 목표 고정
R0-1 모든 TASK 첫 줄: "앞당기는 게이트: G1|G2|둘 다|인프라(서버·저장소)". 없으면 발행 불가.
R0-2 성공 = GOAL.md의 게이트 숫자 통과. 그 밖의 표현은 성공이 아니다.

## 1. 증거
R1-1 모든 수치·판정에는 포인터 1개 이상(로그 파일:행 / SHA-256 / 결과 JSON 키). 없으면 [?]로 표기 → B 자동 반려.
R1-2 손타이핑 숫자 0. "통과/입증/확정/승인" 단어는 B와 사람만 쓴다. 실행자는 숫자와 기준만 쓴다.
R1-3 모든 실행은 `| tee <log>`. 보고는 로그를 복사하지 않고 파일:행을 가리킨다. 인용은 20행 이내.
R1-4 서버 접속이 안 되는 동안 "완료"를 쓰지 않는다. 접속 실패가 곧 보고 내용이다.
R1-5 아직 실행하지 않은 것의 결과값을 미리 적지 않는다("실행 후 결과 원문(값 불문)").

## 2. 불변·안전
R2-1 원본·산출물 덮어쓰기 0, 삭제 0(잘못 둔 파일은 mv). 사전등록 개정은 직전 잠금본 복사 + 절 단위 수정 + `diff -u` 첨부만. 전면 재작성 금지.
R2-2 정본 코드(cts_e1, 정본 함수)는 수정 0. 실험 코드는 새 파일·새 폴더(exe_scratch/…).
R2-3 진행 중 파이프라인(tmux 세션)은 어떤 TASK도 kill·attach·수정하지 않는다. 정지는 감시 스크립트가 정해진 조건에서만.
R2-4 GPU 허용 목록(현재 GPU 0)만. 같은 GPU 동시 실행 0. GPU 4 봉인. 다른 GPU는 escalate 후 사람 허용 시.
R2-5 서버 CPU 작업: `ulimit -v 62914560` · `nice -n 19` · torch.no_grad 기본 · 걸음 간 autograd 그래프 보존 0 · 5분마다 free -g 로그. 위반 스크립트는 실행 0.
R2-6 공유 venv 설치 0. 참고 코드는 /home/shoon/ref/ 격리, 복사 시 출처·커밋·라이선스 머리글.
R2-7 비밀정보(비밀번호·키)는 어떤 파일에도 쓰지 않는다. SSH는 키 인증만.

## 3. 자율 범위
R3-1 되돌릴 수 있는 것(새 파일 실험, 재계산, 재개, 조건 불변 코드 결함 수정 + 사전 점검)은 승인 없이 진행하고 사후 보고.
R3-2 사람에게 묻는 것(escalate/ESC-n.md): GPU 추가, 외부 과금, 삭제·덮어쓰기, 대외 송부, 같은 TASK 3회 연속 FIX, 서버 물리 조치.
R3-3 코드 결함으로 멈추면: 조건·데이터·채점·손실 불변인 결함 → 새 파일 수정 → 학습 문항 2개 사전 점검 → 재개 → 보고. 조건을 바꿔야 하는 결함 → BLOCK.

## 4. 사이클
R4-1 매 사이클 시작: 서버 건강(free -g, nvidia-smi, tmux ls, 파이프라인 로그 마지막 행 시각). 이상이면 SERVER_RECOVER 노드가 최우선.
R4-2 정체 감지: 파이프라인 로그 30분 무변화 또는 TASK가 예상의 2배 초과 → 원인 확인 TASK. 3시간 무진전 → ESCALATE.
R4-3 A는 사이클당 GPU TASK 1개(직렬). CPU-only 진단은 2개까지 병렬.
R4-4 B의 감사 체크리스트 6항, 각 항목 PASS/FAIL + 근거 행: ① 포인터 ② 사전등록 대비 변경 0 ③ 산술 재검산 ④ 서버 무간섭 ⑤ 규칙 위반 ⑥ 게이트 진전.
R4-5 A의 다음 TASK는 직전 AUDIT의 FIX 항목을 먼저 닫아야 발행 가능.
R4-6 가설은 GRAPH.md의 가설 대기열에 "기각 조건"과 함께 등록된 것만 시험한다. 결과를 본 뒤 기준을 바꾸지 않는다.

## 5. 토큰 절약
R5-1 각 에이전트는 자기 inbox + STATE.md + 해당 TASK/REPORT/AUDIT만 읽는다. LEDGER·archive는 검색 요청 시에만.
R5-2 코드베이스 분석은 CODEBASE_MAP.md 1회. 갱신은 변경 파일에 한해.
R5-3 REPORT는 ① 결과 표(수치+포인터) ② 변경 파일 SHA ③ 예상 밖 사건 ④ 서버 상태 1줄. 4절 이내.
R5-4 반복 감시(진행률)는 스크립트가 STATE.md에 쓴다. 에이전트가 폴링하며 토큰을 쓰지 않는다.
R5-5 모델 등급: 감시·상태판 = 스크립트(0 토큰), 실행 보고 = 실행 에이전트, 판정·설계 = 상위 모델(B, A).

## 6. 사람이 보는 것
R6-1 사용자는 STATE.md 상단 10줄(현재 노드·서버·ESC 대기·다음 마일스톤)만 본다.
R6-2 ESC 파일은 한 줄 질문 + 선택지(권고 표시). 사용자는 한 단어로 답한다(예: "허용", "0.25", "보류").
